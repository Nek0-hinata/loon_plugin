# 4KHD 搜索修复：2026-11-22

## 排查结果

基于 `289156759a49f2dfd9b606f23d003018ba4f8334` 检查。上次修复补齐了广告 Worker 路径和注册清理，但没有提供独立搜索提交处理。

本次公开响应对照中，普通英文、中文及空格、加号、百分号等关键词的服务器搜索正常，未将其误报为整站搜索故障。已确认的缺口包括：

- `/?s=cosplay&paged=2` 返回 302 至 `/search/cosplay`，丢失页码；`/search/cosplay/page/2/` 返回 HTTP 200 且标题显示第 2 页。
- 当前 Worker 的搜索分支把已解码的 `s` 直接拼接至 `/search/` 后，并丢弃其他参数。残留 Worker 控制页面时，保留 `?s=` 的原生提交仍可能走这条路径。这里只对下载脚本的字符串表做静态解析，没有执行 Worker 或其广告配置。
- 手机页头输入框默认隐藏，主题脚本克隆表单并绑定搜索图标。正常脚本加载时能提交；故障注入屏蔽主题脚本后，原搜索图标无法打开输入框。该情况用于验证后备处理，不代表已经确认用户设备发生了相同的资源加载失败。

## 修改

- 启用站点的同源 `form[role=search].wp-block-search` GET 表单直接提交到编码后的标准搜索路径，按当前表单获取关键词，避免浮动表单重复 ID 导致读错输入。保留正常隐藏字段、筛选参数和提交按钮字段，保留浏览器必填校验。
- LPX 增加根路径及 `/page/N/` 上 `?s=` 搜索的请求处理，保留页码和其他查询字段，返回不缓存的 302。标准搜索路径不再次跳转。空词、重复关键词、无效编码或页码、POST、API 与其他站点原样放行。
- 主题已处理的浮动搜索点击保持原行为；主题未接管时才创建后备搜索面板。面板支持输入聚焦、点击或回车提交、空词校验、Escape 和面板外点击关闭，重开保留输入。
- 关闭站点开关时不规范化搜索、不注入后备搜索逻辑。保留原有广告拦截、Worker 清理、图片修复和正常搜索事件监听，不增加全局域名拒绝或后台网络请求。
